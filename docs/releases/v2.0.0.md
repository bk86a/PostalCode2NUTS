# PostalCode2NUTS 2.0.0 — Territory awareness

This release teaches the service the difference between an EU **outermost region** and an
**overseas country or territory**, and stops it inventing NUTS codes for places Eurostat does
not classify.

## Why

A postal code in Nouméa is a well-formed French code. It passed validation, fell through to
prefix approximation, matched Monaco's `98000`, and came back as **Alpes-Maritimes** — the
French Riviera, 16,000 km away. Nuuk came back as Nordsjælland. Saint-Pierre-et-Miquelon, in
the North Atlantic, came back as Réunion in the Indian Ocean.

None of those places has a NUTS region, because NUTS classifies the economic territory of the
EU and OCTs are associated with the Union rather than part of it. The right answer was never
a weaker guess — it was to say so.

## What's new

**A `territory` block on every affected response**, naming the territory, its legal status and
whether NUTS covers it:

```json
"territory": {
  "id": "NC", "iso": "NC", "name": "New Caledonia",
  "status": "oct", "administering_country": "FR",
  "legal_basis": "TFEU Part Four, Annex II",
  "note": "Associated with the EU; outside the NUTS classification.",
  "nuts_coverage": "none"
}
```

**22 territory ISO codes now accepted** where they previously returned `400`: `GP` `MQ` `GF`
`RE` `YT` `MF` `GL` `PF` `NC` `WF` `PM` `BL` `TF` `AW` `CW` `SX` `BQ` `SJ` `GI` `JE` `GG` `IM`
(`FO` was already accepted, taking the total to 59 — 60 with UK/ITL configured via
`PC2NUTS_NSPL_URL`). A territory can be reached by its own code or the administering country's, and both give
the same answer: `GL/3900` = `DK/3900`.

**Svalbard and Jan Mayen are now resolvable** — `SJ/9170` → `NO0B2`, `SJ/8099` → `NO0B1`. They
were always in Eurostat's Norwegian file; `SJ` simply was not an accepted country code.

**Aruba, Curaçao, Sint Maarten and the BES islands are reachable for the first time.** They use
no postal codes at all, so they answer on the country code alone.

## What's breaking

**Nullable NUTS fields.** `match_type`, `nuts1`/`nuts2`/`nuts3` and their `_name` and
`_confidence` companions can now be `null`. Widen strict client schemas before upgrading.

**Eight postal ranges stop returning a region.** French `975xx` `977xx` `978xx` `984xx` `986xx`
`987xx` `988xx` and Danish `39xx` now return `200` with null NUTS and a `territory` block:

```
FR/98800  before: FRL03 Alpes-Maritimes, approximate, 0.40
          after:  null, territory: New Caledonia (OCT), nuts_coverage "none"

DK/3900   before: DK013 Nordsjælland, approximate, 0.20
          after:  null, territory: Greenland (OCT), nuts_coverage "none"

FR/97150  before: FRY10 Guadeloupe, approximate, 0.60
          after:  null, territory: Saint-Martin (outermost region), "none"
```

If you measure match rates, expect a small decrease. The answers you lose were wrong.

**The fabricated Faroe Islands codes are gone.** `FO0`/`FO00`/`FO000` never existed in NUTS —
this project invented them. `FO` lookups now return a territory block with null NUTS.

**Territory codes validate against their own ranges.** `GL/2100` returns `404` rather than
Copenhagen's `DK011`, and `SJ/0150` returns `404` rather than Oslo's `NO084`.

## What stays the same

The nine outermost regions keep full coverage and now carry a label: Guadeloupe, Martinique,
French Guiana, Réunion, Mayotte, the Azores, Madeira and the Canary Islands all resolve `exact`
at 1.0 exactly as before.

One deliberate oddity: `FR/97133` Saint-Barthélemy is an OCT, but Eurostat's own French file
carries that code inside Guadeloupe's block. Rather than override Eurostat or silently pass the
result off as ordinary, the service returns `FRY10` flagged
`nuts_coverage: "tercet_entry_only"` — show what the authoritative data contains, and label it.

Montenegro's `ME000` and Albania's block-resolved codes are untouched. Both are genuine
Eurostat codes that merely lack a TERCET file, and neither is fabricated.
