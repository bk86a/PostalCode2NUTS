# PostalCode2NUTS 3.0.1 — Réunion's CEDEX codes come home

A registry fix. French `977xx` and `978xx` are La Réunion CEDEX blocks; the territory registry
had them as postal prefixes of Saint-Barthélemy and Saint-Martin, so a Réunion address in
either block answered with null NUTS and the wrong territory in its `context`.

## Why

Saint-Barthélemy has exactly one postal code, `97133`. Saint-Martin has exactly one, `97150`.
Both were already held as exact entries in the registry, so the `977` and `978` prefixes added
nothing but false positives — and the two blocks they claimed belong to Réunion:

```
FR/97715   Université de La Réunion, Saint-Denis
FR/97743   Académie de La Réunion, Rectorat
FR/97831   Lycée polyvalent Roland Garros, Le Tampon
```

Every one of them was answered as an OCT or as an outermost region Eurostat does not classify,
which is the opposite of the mistake 2.0.0 set out to fix: real NUTS territory reported as
outside NUTS. In the 2026-08 organisation run, 11 of 11 addresses on `977xx` and 63 of 63 on
`978xx` carried Réunion cities, covering some €12.6 M of grant volume.

## What changed

`977` and `978` are now Réunion prefixes. Saint-Barthélemy and Saint-Martin keep their single
exact codes and no prefixes at all.

```
FR/97715   before: null, context Saint-Barthélemy (OCT), nuts_coverage "none"
           after:  FRY40 Réunion, context Réunion (outermost region), "full"

FR/97831   before: null, context Saint-Martin (outermost region), "none"
           after:  FRY40 Réunion, context Réunion (outermost region), "full"
```

## What stays the same

`FR/97133` and `BL/97133` still return `FRY10` flagged `tercet_entry_only` — Eurostat's own row
for Saint-Barthélemy, honoured and labelled. `FR/97150` and `MF/97150` still return null NUTS
with Saint-Martin's `context`: an outermost region for which Eurostat publishes no code.

The five OCT ranges the territory gate exists for are untouched: `975xx`, `984xx`, `986xx`,
`987xx`, `988xx` and Danish `39xx` still answer territory-only.

## Upgrading

No API contract change. Clients that special-cased `977xx` or `978xx` as territory codes should
drop that handling.

## Estimates the gate was hiding

`tercet_missing_codes.csv` already carried `97715`, `97825`, `97831`, `97867` and `97872` as
Réunion at high confidence. They were unreachable: a territory outside NUTS runs tier 1 only,
so the registry's claim on the block overrode the estimate. With the blocks back under Réunion
those rows resolve, and this release adds the fifteen further CEDEX codes the 2026-08 run
observed — `97743` among them — so twenty codes now answer `estimated` `FRY40` at 0.90.

A CEDEX code outside that list has no TERCET row and no estimate, so it reaches `FRY40` through
prefix estimation at `nuts3_confidence` 0.11 — the right region, at a confidence that
understates it. Pinning single-region outermost regions to their NUTS3 in the registry would
settle every one of them at 1.0; that is a cascade change and is not in this release.
